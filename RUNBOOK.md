# Governed content workflow runbook

`start.sh` is intentionally non-destructive: it never installs packages, kills a port owner, migrates, or seeds. Use `scripts/bootstrap.sh` once, review `.env`, apply `scripts/migrate.sh`, and only then run `start.sh`. Demo records require `CONFIRM_DEMO_SEED=yes scripts/seed-demo.sh` and are blocked in production.

The governed migrations store rights evidence, immutable source digests, channel drafts with citations, independent brand/accessibility/fidelity review, human approvals, publication outbox attempts, WordPress delivery receipts, performance snapshots, and audit events. Draft authors cannot supply publishable review scores: an editor or publisher other than the author must affirm brand and accessibility checks and record at least 90% factual fidelity before variant approval; publication rechecks the saved reviewer identity and citations. These checks are human attestations against the cited source, not automated proof that a claim is true. Generated `gap_*` endpoints are retained only as historical source and are no longer mounted. Apply `002_wordpress_delivery_receipts.sql` and `006_performance_source_evidence.sql` before using the delivery and analytics actions. Set `WORDPRESS_TENANT_ID`, `WORDPRESS_SITE_URL` (HTTPS site root), `WORDPRESS_USERNAME`, and `WORDPRESS_APPLICATION_PASSWORD` to enable one tenant-bound web destination. Use a [WordPress application password](https://developer.wordpress.org/rest-api/using-the-rest-api/authentication/) for an account authorized to [create posts](https://developer.wordpress.org/rest-api/reference/posts/). An approved web variant can be delivered by a publisher from the governed screen. Retries use a stable post slug and check the existing published content before creating another post; failures back off and stop after five attempts. A publisher may record analytics counts with an HTTPS report reference and SHA-256 after a delivery receipt exists; those operator-entered counts are not independently verified against a provider API. Do not place credentials in model prompts or audit evidence. Other social/email adapters and automatic provider analytics remain unconfigured.

Apply `007_source_snapshots_and_evidence.sql`, `008_pdf_text_evidence.sql`, and `009_pdf_ocr_evidence.sql` before using the revised governed screen. Registration now computes a SHA-256 digest in the browser from a selected file and records the operator's rights basis and reference URL. The browser then uploads the same file to `PUT /api/workflow/workflows/:id/source` as `application/octet-stream`, with `X-Source-Media-Type` and `X-Source-Filename` headers. The server computes SHA-256 from the received bytes and rejects a mismatch with the registered digest. The database stores the bytes once per workflow and rejects subsequent updates or deletes; identical upload retries are safe. Text files must be valid UTF-8 and at most 1 MiB. PDF, PNG, and JPEG files are accepted up to 5 MiB with basic file-signature checks. The governed screen shows stored text to authorized tenant members and offers an authenticated download of the exact stored bytes. Registered workflows from before this migration can upload the matching source file from the same screen; they cannot draft or publish until they do.

Draft citations must match the registered source URI, optionally with a section fragment. For text sources, a draft also needs at least one exact claim-to-source quote span. Offsets use JavaScript UTF-16 string indexes in the stored decoded text and the draft body; the server checks the exact substrings and source digest at draft creation, independent review, and the scheduling/publication gate. An editor or publisher other than the draft author must confirm they inspected the stored source and evidence before approving the variant.

For a PDF, install Poppler's `pdfinfo`, `pdftotext`, and `pdftoppm`, plus Tesseract on the app host, then choose **Extract PDF text** before drafting. `POST /api/workflow/workflows/:id/source/pdf-text` accepts the already stored PDF, up to five pages and 5 MiB. Pages without selectable text are rendered at bounded size and recognized with Tesseract (`CONTENT_OCR_LANGUAGE`, default `eng`). It stores one immutable derived text record with a second SHA-256, page offsets, and each page's text-layer or OCR label; retries return the saved derivation. Exact quote spans must stay inside one page and include the original PDF SHA-256, derived text SHA-256 and page number. Every quoted page needs a matching `#page=N` citation. The governed screen shows the extracted text and page offsets; reviewers must compare OCR quotes with the downloaded original because recognition can be wrong. Blank PDFs with no usable text remain on the manual download/review path. Extraction is unavailable after a workflow has moved beyond ingestion, so existing drafts cannot silently gain new citation requirements. Extraction workers still need deployment isolation and resource hardening.

These checks bind reviewer-visible evidence to stored bytes and record a human judgment. They do not verify that the operator's URL represents those bytes, that rights claims are authentic, or that each factual claim is true. Existing WordPress delivery and operator-imported analytics behavior remain subject to their separate provider receipts and limits.

Before production: run backend tests and frontend build, migrate against a backup-tested staging database, exercise idempotent provider retries/dead letters, evaluate fidelity and accessibility against a rights-cleared corpus, and obtain content-owner publishing approval.
